# AI 코딩 교실

초등학교 6학년 학생을 대상으로 진행하는 **10차시 AI 코딩 수업용 웹 플랫폼**입니다.

학생은 코딩의 발전 과정과 AI의 특징을 배우고, 좋은 지시문을 작성한 뒤 Canva AI 코드로 자신에게 필요한 앱을 제작합니다. 교사는 학급별 차시 공개, 진행 상황 확인, 결과물 관리와 피드백을 한곳에서 수행할 수 있습니다.

> 현재 상태: 기획 단계  
> 상세 요구사항: [PRD.md](./PRD.md)

## 프로젝트 목표

- 학생이 복잡한 회원가입 없이 수업에 참여할 수 있도록 합니다.
- 10차시의 학습, 활동, 제출과 성찰을 하나의 흐름으로 연결합니다.
- 완성 작품뿐 아니라 프롬프트 작성, 테스트와 수정 과정도 기록합니다.
- 학생이 AI 결과를 그대로 받아들이지 않고 확인·수정하도록 돕습니다.
- 교사가 여러 학급의 진행률과 제출 결과를 간편하게 관리하도록 합니다.
- 개인정보 수집을 최소화하고 학생과 교사의 권한을 분리합니다.

## 핵심 학습 과정

```text
문제 발견
   ↓
AI에게 구체적으로 지시
   ↓
결과 실행 및 확인
   ↓
오류 발견과 수정 지시
   ↓
친구의 사용자 테스트
   ↓
개선 및 성찰
```

## 10차시 구성

| 차시 | 주제 | 핵심 결과물 |
|---:|---|---|
| 1 | 코딩은 어떻게 발전해 왔을까? | 코딩 발전 흐름 정리 |
| 2 | 전통적 코딩과 AI 코딩 | 코딩 방식 비교표 |
| 3 | AI는 무엇을 잘하고 못할까? | 나의 AI 사용 약속 |
| 4 | AI에게 잘 지시하는 방법 | 앱 기획서와 첫 프롬프트 |
| 5 | Canva AI 코드 시작하기 | 수정한 예제 앱 |
| 6 | 하나의 기능을 가진 앱 만들기 | 한 기능 앱 |
| 7 | 앱 기능 설계하기 | 앱 설계도 |
| 8 | 두 가지 이상의 기능을 가진 앱 만들기 | 두 기능 이상 앱 |
| 9 | 나에게 필요한 앱 만들기 | 최종 앱 초안 |
| 10 | 앱 공유와 개선 | 최종 앱과 제작 성찰 |

## 주요 사용자

### 학생

- 학급 코드, 학생 번호와 PIN으로 참여
- 공개된 차시 학습 및 활동 수행
- 프롬프트와 앱 기획서 작성
- 제작 과정과 오류 수정 기록
- Canva 결과물 링크 제출
- 친구 작품 테스트 및 구조화된 피드백

### 교사

- 교사 계정 로그인
- 학급 및 학생 관리
- 차시 공개·잠금과 제출 기한 설정
- 학생별 진행 상황 및 결과물 확인
- 교사 피드백 작성
- 공유 작품 승인 및 동료 피드백 관리
- 학급 활동 데이터 내려받기

## MVP 범위

초기 개발 범위는 다음과 같습니다.

- 교사 로그인
- 학급 생성과 학생 번호·PIN 등록
- 학생의 학급 참여
- 10차시 목록과 차시 공개·잠금
- 차시별 학습 자료, 활동과 형성 퀴즈
- 프롬프트 빌더
- 앱 기획 캔버스
- 제작 및 오류 수정 기록
- Canva 결과물 링크 제출
- 학생 진행 현황과 교사 피드백
- 입력 자동 저장 및 저장 상태 표시

작품 갤러리, 모둠 작업, 콘텐츠 편집, CSV 내보내기와 OpenAI API 기반 피드백은 MVP 이후 기능으로 계획합니다.

## 권장 기술 구조

기술 스택은 개발 착수 전에 확정합니다. 현재 PRD의 권장 구조는 다음과 같습니다.

```text
학생·교사 웹 브라우저
          ↓
React 기반 반응형 웹 애플리케이션
          ↓
백엔드 API 및 권한 검증
          ↓
PostgreSQL 호환 관리형 데이터베이스
          ↓
선택 기능: OpenAI API
```

- **프론트엔드:** React 기반 반응형 웹 애플리케이션
- **백엔드:** 서버 렌더링 프레임워크의 서버 기능 또는 별도 Node.js API
- **데이터베이스:** PostgreSQL 호환 관리형 데이터베이스
- **인증:** 교사 계정 + 학급 코드·학생 번호·PIN 기반 학생 세션
- **결과물:** 초기에는 파일 업로드 없이 Canva 공유 URL 제출
- **배포:** HTTPS, 환경 변수, 로그와 롤백을 지원하는 관리형 호스팅

Codex는 애플리케이션 개발을 지원하지만 운영용 데이터베이스 자체를 제공하지 않습니다. 여러 학생이 온라인으로 함께 사용하려면 별도의 데이터베이스와 호스팅 서비스가 필요합니다.

## 프로젝트 구조

현재 저장소는 기획 문서만 포함합니다. 개발 시작 후 다음과 같은 구조를 권장합니다.

```text
.
├─ README.md
├─ PRD.md
├─ docs/                 # 화면 설계, API와 운영 문서
├─ src/                  # 웹 애플리케이션
│  ├─ app/               # 페이지 및 라우팅
│  ├─ components/        # 공통 화면 구성 요소
│  ├─ features/          # 차시, 프롬프트, 제출 등 기능
│  └─ lib/               # 인증, 데이터 접근, 공통 기능
├─ public/               # 이미지와 정적 자료
├─ tests/                # 자동화 테스트
└─ database/             # 스키마와 마이그레이션
```

실제 구조는 선택한 프레임워크에 맞춰 조정합니다.

## 개발 순서

1. 운영 학급 수, 학생 식별 방식과 데이터 보존 정책을 확정합니다.
2. 기술 스택, 데이터베이스와 호스팅 서비스를 선택합니다.
3. 학생 홈, 교사 대시보드와 1차시 흐름의 시제품을 만듭니다.
4. 인증, 학급, 학생, 차시와 활동 데이터를 연결합니다.
5. 프롬프트 빌더, 앱 기획과 결과물 제출 기능을 구현합니다.
6. 전체 10차시 콘텐츠를 입력하고 화면 접근성을 점검합니다.
7. 한 학급을 대상으로 시범 운영한 뒤 문제를 수정합니다.
8. 작품 공유와 동료 피드백 등 후속 기능을 추가합니다.

## 개발 착수 전 결정사항

- 실제 운영 학급 수와 학급당 최대 학생 수
- 학생 식별 방식: 번호 또는 별칭 병행 여부
- 학생 PIN 배부 및 초기화 방법
- 교사 인증 방식과 학교 계정 사용 여부
- 데이터베이스 및 호스팅 서비스
- 학생 데이터 보존 기간과 삭제 절차
- Canva 결과물 공유 범위와 학교 계정 정책
- 개인·모둠 제작을 적용할 차시
- 동료 피드백의 MVP 포함 여부
- OpenAI API 기능 도입 여부와 예산

전체 결정 목록과 기능별 수용 기준은 [PRD.md](./PRD.md)를 참고하세요.

## 개인정보와 안전 원칙

- 학생 이메일, 전화번호와 생년월일은 수집하지 않습니다.
- 실명 대신 학급, 학생 번호 또는 교사가 정한 별칭을 사용합니다.
- 학생 PIN은 원문으로 저장하지 않고 안전하게 처리합니다.
- 학생 결과물은 원칙적으로 같은 학급 안에서만 공유합니다.
- 작품과 동료 피드백의 공개 여부는 교사가 관리합니다.
- OpenAI API 키와 데이터베이스 관리자 키를 학생 브라우저에 노출하지 않습니다.
- 운영 전 학교의 개인정보 처리 기준과 외부 서비스 이용 조건을 확인합니다.

## AI 기능 원칙

MVP는 외부 AI API 없이도 수업할 수 있도록 설계합니다. 프롬프트 템플릿과 규칙 기반 체크리스트를 먼저 사용하며, OpenAI API 기반 개선 힌트는 선택 기능으로 추가할 수 있습니다.

AI 기능을 추가할 때는 다음 원칙을 지킵니다.

- AI가 만든 안내임을 학생에게 표시합니다.
- AI 응답을 정답 판정이나 성적 산출의 유일한 근거로 사용하지 않습니다.
- 학생이 입력한 개인정보가 외부 AI로 전송되지 않도록 안내하고 검증합니다.
- AI의 결과를 학생이 직접 실행하고 확인하도록 합니다.

## 완료 기준

MVP는 최소한 다음 상황을 지원해야 합니다.

- 교사가 학생 30명이 포함된 학급을 생성할 수 있습니다.
- 학생이 1분 안에 학급에 참여할 수 있습니다.
- 학생이 교사가 공개한 차시만 열 수 있습니다.
- 새로 고침 후에도 저장된 활동 내용이 유지됩니다.
- 학생이 프롬프트, 앱 기획과 오류 수정 기록을 저장할 수 있습니다.
- 학생이 Canva 결과물 링크를 제출할 수 있습니다.
- 교사가 학생별 진행 상황과 제출물을 확인하고 피드백할 수 있습니다.
- 다른 학생이나 다른 학급의 비공개 데이터에 접근할 수 없습니다.
- 학교 네트워크가 잠시 끊겨도 작성 내용이 즉시 사라지지 않습니다.

## Supabase 백엔드 연결

학생은 이메일과 비밀번호로 자신의 계정을 만들고 로그인합니다. 회원가입할 때 입력한 이름·6학년 반·번호는 학생 프로필에 저장되며, 각 학생은 RLS(Row Level Security) 정책에 따라 자신의 프로필과 학습 기록만 읽을 수 있습니다.

1. Supabase 프로젝트의 **Authentication → Providers → Email** 로그인을 활성화합니다.
2. Supabase **SQL Editor**에서 `web/supabase/schema.sql`을 실행합니다.
3. `web/.env.example`을 참고하여 `web/.env.local`에 프로젝트 URL과 Publishable key를 입력합니다.

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_SUPABASE_PUBLISHABLE_KEY
```

현재 저장되는 데이터는 학생 이름·학년·반·번호와 1차시의 현재 단계, 퀴즈 점수, 한 문장 정리, 완료 여부입니다. Service role key는 브라우저나 저장소에 절대 넣지 않습니다. 교사용 계정과 권한은 아직 구현하지 않았습니다.
